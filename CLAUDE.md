# Когда спрашивать, а когда делать

- Делай сразу: мелкие правки, исправление очевидных багов, всё, что легко откатить.
- Сначала спроси: если неясны бизнес-логика, формат данных, контракт API или ожидаемый UI. Контракты API никогда не выдумывай, запрашивай.
- Архитектуру, формат хранения данных и мобильную адаптивность решай сам, без ожидания моего «ок». Просто расскажи, какие решения принял и почему. Если уточнение нужно, я скажу.
- В серьёзных развилках выбери вариант сам и напиши «Я рекомендую этот вариант» с короткой причиной. В мелочах решай молча.
- Перед крупной задачей кратко перечисли шаги, но можно начинать сразу, не дожидаясь ответа.
- Вопрос «можешь ли ты это сделать?» — это вопрос о возможности, а не просьба. Ничего не делай: ответь, возможно ли это, и если есть несколько способов, предложи варианты.
- Мелкие допущения делай сам, но помечай: «Допускаю, что…».
- Сразу предупреждай, если задача ломает архитектуру или адаптивную вёрстку.

# Проект

«Тренируем собачку»: справочник по тренировке собак. Записи (команды, упражнения, игры, игрушки) с категорией, тегами и картинками, публичные страницы и админка. Подробности: [README.md](README.md), ТЗ: [техническое задание.md](техническое%20задание.md) и [расширенное техническое задание.md](расширенное%20техническое%20задание.md).

- Стек: FastAPI + Jinja2 + SQLAlchemy + SQLite + Pydantic. В браузере: Quill (редактор текста) и Vue 3 (менеджер картинок), оба лежат локально в `static/vendor/`, без сборщика.
- Запуск: `python main.py` из корня проекта. Тесты: `python -m pytest`. Команды терминала (выгрузка, импорт, копия базы): `python -m cli`.
- Настройки читаются из `.env` (образец: `.env.example`), описаны в `core.py`. Файл `.env` не читай и не выводи.
- Миграций нет. Меняешь схему БД: `python -m cli export`, удалить `data/app.db`, запустить приложение, `python -m cli import`.
- Слои: роут (`routes/`) -> функции работы с БД (`data/`) -> шаблон (`templates/`). Запросы и изменения данных живут в `data/`, роут только вызывает их (точечные `session.get` в роутах допустимы).
- HTML из редактора всегда очищается через `utils.text.sanitize_html`, в том числе при импорте. В шаблонах `|safe` только для уже очищенного `record.text`.

# Документация

- У каждой папки-модуля есть свой `README.md`: `data/`, `routes/`, `templates/`, `static/`, `utils/`, `tests/`. В корне лежит общий `README.md`.
- Изменил модуль (добавил, переименовал или удалил файл, поменял маршрут, модель, настройку): в той же правке обнови его README и, если надо, корневой.
- Создал новую папку-модуль: сразу добавь в неё `README.md` в том же формате (назначение, таблица файлов, что важно знать) и строку в таблицу структуры корневого `README.md`.
- В README только то, что есть в коде сейчас. Планы и недоделки живут в `todo.txt`, не в README.
