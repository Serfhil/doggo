# data

Всё, что связано с базой данных: SQLite, SQLAlchemy-модели, схема формы записи, запросы и изменения
данных, экспорт и импорт JSON.

## Файлы

| Файл | Назначение |
|------|-----------|
| `base.py` | `Base` — общий родительский класс всех моделей |
| `models.py` | Таблицы: `Record`, `Category`, `Tag`, `Image`, `DailyVisits` и связующие таблицы |
| `schemas.py` | `RecordForm` (данные формы записи и правила проверки), `check_name` (имя тега/категории) |
| `db.py` | Движок, сессии, `init_db`, `seed_defaults`, зависимость `get_db` |
| `records.py` | Список с фильтрами и пагинацией, сохранение и удаление записи |
| `taxonomy.py` | Теги и категории: создание, переименование, удаление, объединение, перенос записей |
| `images.py` | Картинки записи: добавление, подпись (alt), порядок, удаление |
| `exchange.py` | Экспорт и импорт записей в JSON |
| `app.db` | Файл базы (создаётся автоматически, в git не попадает) |

## Модель данных

- `Record` — запись: `title`, `description`, `text` (очищенный HTML), `category_id`, `is_published`,
  `created_at`, `updated_at`, `search_text` (название и описание в нормализованном виде для поиска).
  Номера (`id`) удалённых записей не выдаются повторно (`AUTOINCREMENT`).
- `Category` — категория, у записи ровно одна. Удалить можно только неиспользуемую.
- `Tag` — тег, у записи их может быть сколько угодно (связь через `record_tag`).
- `Image` — картинка записи: файл `<uuid>.webp`, подпись `alt`, порядок `position`.
  Первая по порядку показывается на карточке.
- `record_related` и `record_prerequisite` — связи «связанные записи» и «сначала освой».
  Сейчас интерфейса для них нет, они участвуют только в экспорте и импорте.
- `Record.video_url`, `Record.views` и таблица `DailyVisits` заведены под будущее: видео
  включается через `VIDEO_ENABLED`, счётчики пока не используются.
- Названия тегов и категорий сравниваются через `name_key` (без учёта регистра, `ё` = `е`).
  Так «Лёгкий» и «легкий» считаются одним тегом.

## Функции

| Модуль | Функция | Что делает |
|--------|---------|-----------|
| `db.py` | `init_db()` | Создаёт таблицы и заполняет пустую базу категориями и тегами |
| | `get_db()` | Зависимость FastAPI: одна сессия на запрос |
| | `make_engine(url)` | Движок; `"sqlite://"` даёт базу в памяти (для тестов) |
| `records.py` | `list_records(...)` | Страница записей (новые первыми) и общее число; фильтры: категория, тег, поиск, статус |
| | `get_record(id)` | Запись или `None` |
| | `save_record(...)` | Создаёт или обновляет запись вместе с тегами |
| | `delete_record(id)` | Удаляет запись и файлы её картинок |
| `taxonomy.py` | `add_tag`, `add_category`, `rename`, `delete_tag`, `delete_category` | Правка справочников, ошибки приходят как `TaxonomyError` |
| | `merge_tags(source, target)` | Все записи с тегом `source` получают `target`, `source` удаляется |
| | `move_category_records(source, target)` | Переносит записи в другую категорию |
| | `get_or_create_tag/category` | Найти по имени или создать |
| `images.py` | `add_image`, `set_alt`, `reorder`, `delete_image` | Операции с картинками записи |
| `exchange.py` | `export_data(session)` | Все записи в виде словаря для JSON |
| | `import_data(session, payload, replace)` | Добавляет и обновляет записи по `id`, всё или ничего |

Начальные данные (только в пустой базе): категории `команда`, `упражнение`, `игра`, `игрушка`;
теги `Лёгкий`, `Средний`, `Тяжёлый`.

## Экспорт и импорт

- Формат: `{"schema_version", "exported_at", "records": [...]}`. Состав полей записи задан в
  `RecordExport` (`exchange.py`), это единственное место, где он описан.
- Новое текстовое поле записи: колонка в `models.py` + поле в форме (`schemas.py`, шаблон) + строка в `RecordExport`.
- Импорт сначала проверяет весь файл: при любой ошибке в базе ничего не меняется.
  Неизвестные поля игнорируются с предупреждением. HTML текста при импорте очищается так же, как в форме.
- `replace=True` стирает все записи, теги и категории. Доступно только из терминала (`python -m cli import --replace`).
- Картинки в JSON не входят: выгружается только текстовая часть.

## Важно знать

- Путь к базе берётся из настройки `DATABASE_PATH` (по умолчанию `data/app.db` от корня проекта),
  поэтому запуск из другой папки базу не «теряет».
- Включены внешние ключи SQLite и режим WAL. Рядом с базой появляются `app.db-wal` и `app.db-shm`:
  это нормально, в git они не попадают.
- Миграций нет: `create_all` не меняет существующие таблицы. Порядок смены схемы описан в корневом README.
- В тестах `get_db` подменяется на базу в памяти, настоящая БД не затрагивается.
