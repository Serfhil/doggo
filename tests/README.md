# tests

Тесты на pytest. Запуск из корня проекта:

```bash
python -m pytest
```

Сейчас 40 тестов, все проходят.

## Файлы

| Файл | Что проверяет |
|------|---------------|
| `conftest.py` | Общие фикстуры и `make_form` (готовые данные формы записи) |
| `test_public.py` | Главная и пустое состояние, только опубликованные записи, поиск по-русски без учёта регистра, фильтры, пагинация, страница записи и ссылка «назад», HTML-страницы 404, `/health` |
| `test_admin_records.py` | Создание, правка, удаление записи; ошибки формы; черновик; очистка HTML; номера не переиспользуются; предпросмотр; поиск в админке; замена `&nbsp;` |
| `test_taxonomy.py` | Уникальность тегов без учёта регистра и `ё`; переименование, удаление, объединение тегов; защита используемой категории; перенос записей |
| `test_images.py` | Загрузка и уменьшение, миниатюра, удаление метаданных, отказ для не-картинок, GIF и больших файлов, лимит количества, подпись/порядок/удаление, удаление файлов вместе с записью, обложка на главной |
| `test_exchange.py` | Формат выгрузки, круговой обход «экспорт → замена → импорт», добавление и обновление, отказ при неверном файле без изменений базы, очистка HTML при импорте, битые связи |

## Как изолированы тесты

- Фикстура `session_factory` создаёт БД **в памяти** (`sqlite://` + `StaticPool`) и заполняет её категориями и тегами по умолчанию.
  Настоящий `data/app.db` не затрагивается.
- Фикстура `client` подменяет зависимость `db.get_db` через `app.dependency_overrides`, направляет `UPLOAD_DIR`
  во временную папку и после теста возвращает приложение в исходное состояние.
- Фикстура `category_id` отдаёт `id` первой категории.

## Как добавить тест

Возьми фикстуру `client` (HTTP-запросы) и при необходимости `session_factory` (проверить, что лежит в базе).
Готовую форму записи даёт `make_form(category_id, **изменения)`.
